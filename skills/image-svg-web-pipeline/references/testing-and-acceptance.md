# 測試、整體驗收、README

## 1. 測試（docs/TESTING.md）

不裝套件：Node 端用內建 `node:test`，瀏覽器端是一頁自己跑的測試頁。

### Node 端（`node --test "tests/*.test.mjs"`，約 1 秒）

| 檔案 | 測什麼 |
|---|---|
| `data-snapshot.test.mjs` | 正式資料快照：總數、各分組、各狀態加總等於總數，跟匯入報告逐欄一致；ID 格式、不重複、和 id-map 對得上；公開 JSON 只有規定欄位、沒有個資 |
| `cascade.test.mjs` | 狀態動作的連動規則、hash 寫入讀回、不合法的值被忽略 |
| `urlcheck.test.mjs` | 格式檢查的接受／拒絕清單；正式資料裡的現有值全部通過；**和匯入程式（Python）跑同一批輸入，結果逐筆比對** |
| `edge.test.mjs` | 用 `tests/fixtures/edge/` 的小資料：空分組、全部完成、沒有資料的分類 |
| `env.test.mjs` | 開發／正式環境判斷的邊界；正式環境開關打不開 |
| `submission.test.mjs` | 後端規則（D1 用 `node:sqlite` 代替，直接跑 `migrations/` 的 SQL） |

需要 DOM 的模組用 `tests/helpers.mjs` 的假 `document`。

### 瀏覽器端（`python tests/serve_tests.py`，打開 http://localhost:8766/）

- 測試伺服器提供：測試頁 `/`、正式網頁 `/web/…`、邊界資料版 `/fx/edge/…`（同一份網頁換資料）、假 API（收紀錄、可以讓下一次回 500、可以取回收到的內容）。
- 同時在 `127.0.0.2` 開一個埠，網頁會當成正式環境，測試頁跑完開發環境項目後自動去跑正式環境項目。
- 用 iframe 設尺寸跑桌機版、手機版，實際點選、量尺寸、檢查文字。
- **跑的時候視窗要看得到**，不然 ResizeObserver 不觸發，尺寸相關項目假失敗。用 Claude 的瀏覽器窗格跑時，先確定窗格是顯示狀態。
- 依賴外部服務即時狀態的檢查（例如 Turnstile 測試金鑰瞬間就通過）容易不穩定，這類情況交給後端單元測試，不要在瀏覽器測試裡搶時間差。

### 測試發現問題

修好、在 TESTING.md 的結果表記「畫面 / 原本 / 修正後」。發現但不修的差異也記下來並說明為什麼不影響。

## 2. 整體驗收（docs/ACCEPTANCE.md）

逐條核對 PLAN §6 的每一項驗收標準：

```markdown
## 0. 結論
| 項目 | 結果 |   ← 全部通過？自動測試幾項？要人決定的幾項？只能人工驗的幾項？

## 1. 逐條核對
| # | 任務 | 驗收標準 | 結果 |   ← 每列 ✅ 加一句證據或連到細節小節

### 1.x 細節（量測表、截圖說明）

## 2. 要你決定的
<驗收時發現、不是 bug 但需要取捨的事，每項給建議>

## 3. 只能人工驗的
<讀屏軟體、系統字級 200%、瀏覽器縮放 125%、減少動態效果…，寫清楚怎麼驗>
```

- 匯入要重跑兩次比對輸出。
- 每個尺寸實際量：有沒有捲軸、各區塊尺寸、標籤重疊、出界、壓到保留區。
- 「要你決定的」全部有結論後，PLAN 任務狀態才改 ✅。

## 3. README（收尾）

給下一個接手的人（也可能是下一個 Agent）：

1. 這是什麼、正式網址。
2. 使用的技術，以及為什麼這樣選（無框架、無建置、Cloudflare 免費額度）。
3. 資料夾說明。
4. 日常使用：更新資料 → 重跑匯入 → 測試 → 部署；匯出回報 → 人工審核 → 寫回 `review-decisions.csv`。
5. 測試和部署的指令。
6. **交給別人時要改的地方**：網站名稱出現的所有檔案、資料來源、底圖和座標檔、Turnstile 網域和金鑰、D1 id、Pages 專案名稱。
7. 隱私：哪些檔案有個資、為什麼不進 git。
8. 文件索引（docs/ 每一份一句話）。

改網站名稱之類的全域修改，先用 grep 列出所有出現的地方給人看，確認範圍（例如「只改網頁，不改雲端小工具名稱」）再改。
