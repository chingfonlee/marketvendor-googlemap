# 設計圖 → SVG → 元件盤點

## 1. 設計基準（階段 0）

目標：把一張設計圖變成「可討論、可重現、可版本控制」的 SVG 元件庫，作為人和 Agent 之後所有溝通的共同參照。

### 資料夾

```
design/
├─ reference/        原始設計圖（mockup.webp 等），只讀
├─ assets/           從設計圖裁切的插畫 PNG（crop_assets.py 產生）
│  └─ final/         生圖 Agent 交付、已驗收的正式素材
├─ svg/
│  ├─ atoms/         色彩 tokens、圖示 sprite、按鈕、狀態徽章、圖釘
│  ├─ components/    頁面上的區塊（頁首、進度卡、篩選、清單、地圖…）
│  └─ pages/         整頁（桌機、手機）
├─ tools/            產生器：crop_assets.py、build_svg.py、label_overlay…
├─ asset-briefs/     給生圖 Agent 的需求包
├─ README.md         組件樹、怎麼重跑產生器
├─ REVIEW.md         SVG 審查報告（§2）
└─ DECISIONS.md      設計決定紀錄
```

### 做法

1. **裁切素材**：`crop_assets.py` 列出每塊插畫在設計圖上的矩形，裁成 PNG。只裁插畫（角色、Logo、底圖），不裁文字和介面。
2. **用產生器畫 SVG**：`build_svg.py` 一支腳本產生全部 SVG。原則：
   - **所有組件都用整頁座標**繪製，組件檔只是用 `viewBox` 框出頁面上的一塊。這樣組件和整頁位置完全一致，之後重組時不用猜。
   - 色彩、狀態（key、名稱、主色、淺底、文字色）在腳本開頭定義成表，全部 SVG 共用。
   - 文字用系統中文字型堆疊：`'Noto Sans TC','PingFang TC','Microsoft JhengHei',sans-serif`。
   - 插畫用相對路徑 `<image href="../../assets/…">` 引用，不內嵌。
3. **寫組件樹**：`design/README.md` 用樹狀圖列出 AppShell → 區塊 → 子元件，每個節點標對應的 SVG 檔。這張樹就是之後 HTML 結構的藍本。
4. **commit 當設計基準**，並在 PLAN 記下 commit hash。之後任何設計變更都能跟這個基準比較。

改設計時改產生器再重跑，不手改 SVG——手改的 SVG 下次重跑就不見了，而且人看不出改了什麼。

### 給人看

把 `pages/*.svg` 在瀏覽器打開給人比對原圖。有差異就在這階段修，因為後面所有規格都以這些 SVG 為準。

## 2. SVG 審查（階段 2 前半）

設計圖拆出來的 SVG 幾乎一定**不適合直接當網頁元件**。審查時逐檔檢查這幾點，寫成 `design/REVIEW.md`：

| 檢查 | 常見問題 | 結論 |
|---|---|---|
| JS 能不能定位 | `class`、`data-*` 數量為 0，元素都是沒名字的 `<g>`、`<text>` | 互動元件改用 HTML |
| 重複 | 同一個圖釘外形畫了 27 次，沒用 `<symbol>`／`<use>` | 改成模板，JS 產生實例 |
| 寫死的資料 | 店名、數字、日期直接寫在 `<text>` | 資料區塊改用 HTML `<template>` |
| 底圖污染 | 底圖 PNG 本身畫了圖釘、標籤、對話框 | 底圖要重做或修圖，動態元素交給 HTML 層 |
| id 衝突 | `clip1`、`shadow` 在多個檔案各定義一次 | 放進同一頁前加前綴，或改用 CSS |

可以沿用的通常是：座標系統、狀態配色、圖示、產生器本身。

審查表格欄位：檔案、用途、分類（固定／重用／數據／互動）、可重用、需動態更新、建議形式（SVG／模板／HTML／參考）。**只讀不改**，結論交給人確認。

## 3. 元件盤點（階段 2 後半）

對照 PLAN 的畫面需求，把每個元件歸類，寫成 `docs/SVG_COMPONENTS.md`：

### 分類

- **固定**：直接沿用（色彩 tokens、圖示 sprite、Logo、吉祥物）。
- **調整**：有現成 SVG 或素材，要改內容、配色或結構（例如圓環從 6 段改 3 段、登入卡改成補交卡）。
- **新增**：設計稿裡沒有，要新做（例如縣市標籤、手機版卡片格）。
- **不用**：列出來並寫原因（例如沒有品類資料所以不放食物圖示）。

### 每列要寫

| 欄 | 說明 |
|---|---|
| 元件 | 名稱 |
| 來源 | 對應的 SVG 或素材檔 |
| 形式 | `HTML`（SVG 只當參考）／`SVG`／`模板`（`<template>` 或 `<symbol>`）／`PNG` |
| 要改的地方 | 具體到文字、數量、顏色 |
| 開關 | 受哪一組開發開關控制（見 web-build.md §6），讓之後每個元件都能單獨關掉來檢查 |

新增元件再加「優先」（P0／P1）。

### 素材替換表

設計稿暫用的素材 → 正式素材 → 狀態（✅ 已替換／待生圖／不用）。這張表讓人一眼看出還差哪些圖要生。

### 原則

- 會隨資料變的文字（名稱、數字、狀態、按鈕）**一律由網頁產生**，不畫進圖片。
- 互動元件用 HTML `<button>`：原生支援鍵盤、焦點、讀屏，中文排版也比 SVG `<text>` 穩定。
- 圖示保留成 SVG sprite（`<symbol>` + `<use>`）。

停下來讓人確認盤點表，特別是「調整」和「不用」兩類——這是範圍的實際邊界。
