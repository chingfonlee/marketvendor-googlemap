互動規則：

- 點縣市標籤（手機是縣市卡片）或在左側選縣市，兩邊同步，地圖、清單、統計共用同一份篩選狀態。
- 選了縣市：右上換成該縣市的市場清單，進度圓環改算該縣市；其他縣市標籤變淡。
- 選了市場：右下顯示該市場的攤商。
- 切換縣市時，原本選的市場和攤商清單一起清掉、換成新縣市的內容。
- 未參與的 14 個縣市只留在底圖上，沒有標籤，也不能點。
- 狀態按鈕只篩選清單，不影響圓環。

## 3. 狀態與完成率

主畫面只有三種狀態：

| 狀態 | key | 定義 |
|---|---|---|
| 已完成 | `verified` | 連結已經確認是這家店 |
| 待確認 | `submitted` | 有連結，但還沒確認。來源可能是搜尋找到的候選，或攤商補交的新連結 |
| 未提交 | `not_submitted` | 沒有連結 |

- **完成率 = 已完成 ÷ 總數（目前 347）**。有網址不等於完成。
- **有問題**（例如歇業、對錯店、家數不符）不做成狀態按鈕，記在 [DATA_ISSUES.md](DATA_ISSUES.md) 另外人工處理。這些攤商在主畫面仍依有沒有連結，顯示為待確認或未提交，所以三種狀態加起來等於總數。
- 退攤、放棄輔導：排除，不算進總數，只留在匯入報告裡。

狀態轉換：

| 從 | 到 | 條件 |
|---|---|---|
| 未提交 | 待確認 | 搜尋找到候選連結，或攤商補交連結並通過格式檢查 |
| 待確認 | 已完成 | 確認連結正確（確認方式見 §5） |
| 待確認 | 待確認 | 攤商補交了不同的連結：換成新連結，舊的留在紀錄裡 |
| 已完成 | 已完成 | 已完成的攤商又補交新連結：只存成紀錄，不覆蓋，由人工決定要不要換 |

上線時的數字：已完成 0、待確認 217、未提交 130，合計 347（2026-10-31，見 [STATS.md](STATS.md)，用 `scripts/stats.py` 重算）。

## 4. 資料匯入

- **輸入**：Excel，只讀，先複製到暫存檔再讀，避開開檔鎖定。
- **輸出**：
  - `web/data/markets.json`：市場 id、名稱、縣市、類型、攤商數、各狀態數量。類型決定市場縮圖，Excel 沒有這個欄位，由匯入程式依下表指定：
    - `night_market` 夜市：華西街、南機場、旱溪、大慶、鄭仔寮花園、臺東觀光夜市
    - `traditional_market` 傳統市場：永春、五股、興國、大園、新竹東門、龍華、三民第一
    - `other` 美食廣場・商圈：瑞芳美食廣場、西門淺草青春新天地
  - `web/data/vendors.json`：攤商 id、市場 id、店名、狀態、Google 地圖連結。
  - `reports/import-report.md`：各市場和各狀態的家數，與總表比對，以及警告清單。
  - **不輸出**負責人、電話、地址、營業時間。
- **人工決定**：記在 `data/review-decisions.csv`（排除、改名、確認、換連結，每筆附原因和日期），重新匯入時套用，不改 Excel。[DATA_ISSUES.md](DATA_ISSUES.md) §2 已決定的項目（排除退攤、放棄輔導等）也寫在這裡。
- **固定 ID**（之後進資料庫直接當主鍵）：
  - 市場 `m01`～`m15`、攤商 `m01-v001` 這種格式，第一次產生後存進 `data/id-map.json`，之後不變、不重複使用。市場用總表名稱對應，攤商用「市場 + Excel 店名」對應，所以分頁順序、總表序號、名單順序變了 ID 都不變。
  - ID 只是名字：程式不能從 ID 拆出市場，要看 `market_id` 欄位。
  - Excel 改了店名或市場名稱：在 `review-decisions.csv` 加 `same_as`，新名稱沿用舊 ID（市場那一列 `market_id` 留空）。沒加的話，攤商會拿到新 ID，報告列出沒用到的舊 ID；市場則直接停下來，要求加 `same_as` 或指定新市場的類型。
- **網址檢查**（離線）：
  - 只接受 Google 地圖網址（`maps.google.com`、`www.google.com/maps`、`maps.app.goo.gl`、`goo.gl/maps`）。
  - 解析出 cid 或 place_id。
  - 不同攤商用同一個地點時列警告；何記 1、2 號店已列為例外。
- **可以重複執行**：同一份 Excel 跑兩次，輸出完全相同。

## 5. 攤商補交與確認連結

不需要註冊。流程：

1. 選縣市 → 市場 → 攤商。
2. 畫面顯示這家店目前的連結（有的話），可以點開到 Google 地圖看。
3. 攤商擇一操作：
   - **「這是我的店」**：確認現有連結。
   - **「不對／沒有，我貼正確的網址」**：貼上 Google 地圖網址。
4. 送出後顯示「已收到，待確認」。

規則：

- **不收任何聯絡資料**。表單上註明「會記錄送出時間與 IP，只用來防止重複和濫用」。
- 送出的資料一律存成**待處理紀錄**，不直接改公開資料。
- 防重複：同一攤商、同一網址、24 小時內只收一次。
- 防濫用：同一 IP 每小時有送出上限；網址長度和網域檢查；之後上 Cloudflare 時再加 Turnstile。
- 紀錄格式（之後可以匯出成 CSV）：

  | 欄位 | 說明 |
  |---|---|
  | `submitted_at` | 送出時間（台北時間） |
  | `ip` | 送出者 IP |
  | `county`、`market_id`、`market_name` | 縣市、市場 |
  | `vendor_id`、`vendor_name` | 攤商 |
  | `action` | `confirm`（確認現有連結）或 `update`（貼新網址） |
  | `url`、`place_key` | 網址，以及解析出的 cid 或 place_id |
  | `status_before` | 送出時這家店的狀態 |
  | `review_result`、`reviewed_at`、`note` | 人工處理結果，送出時留空 |

- 存放位置等 Cloudflare 建立時再決定（D1 加 CSV 匯出，或其他方式）。在那之前，網頁先做好表單和格式檢查，用開發開關模擬送出。
- 待處理紀錄經人工確認後，寫進 `data/review-decisions.csv`，重新匯入，公開狀態才會變成已完成。
