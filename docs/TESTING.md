- 更新日期：2026-11-01

## 1. 怎麼跑

Node 端（資料、規則、紀錄格式），約 1 秒：

```bash
node --test "tests/*.test.mjs"
```

瀏覽器端（真的畫面、點選、版面），約 10 秒：

```bash
python tests/serve_tests.py
```

打開 <http://localhost:8766/>，頁面會自動跑完，最上面顯示「N 項全部通過」或失敗的項目和原因。

測試伺服器的路徑：

| 路徑 | 內容 |
|---|---|
| `/` | 測試頁（`tests/browser/`） |
| `/web/…` | 正式網頁和正式資料 |
| `/fx/edge/…` | 同一份網頁，`data/*.json` 換成 `tests/fixtures/edge/`（邊界案例） |

### 2.3 網址檢查（`tests/urlcheck.test.mjs`）

- 接受：`maps.google.com`、`www.google.com/maps`、`google.com.tw`、`cid`、`place_id`、`query_place_id`、長網址裡的 `!1s0x…:0x…`。短網址接受但不解析地點。
- 拒絕：不是網址、不是 http(s)、別的網域（包含 `maps.google.com.evil.com` 這類）、`goo.gl` 不是 `/maps`、短網址不完整、找不到地點、超過 2048 字（剛好 2048 字可以）。
- 手機分享的文字（前面帶店名、後面帶全形標點）取出網址。
- 正式資料裡 217 個現有連結全部通過；共用同一個地點的只有 `review-decisions.csv` 裡 `share_place` 的何記 1、2 號店。
- **和匯入程式一致**：把 `scripts/import_excel.py` 的 `check_url` 抽出來用 Python 跑同一批網址，結果逐筆比對（兩邊刻意不同的 `google.com.tw`、短網址不比）。找不到 Python 時這項跳過。

### 2.4 邊界案例（`tests/edge.test.mjs`＋瀏覽器測試）

- 空市場：清單空的、各狀態 0、沒有 NaN；不影響所屬縣市的統計。
- 全部完成：完成率 100%；篩未提交時是空清單，提示和按鈕正確。正式資料全部改成已完成時，每個縣市和全台都是 100%。
- 沒有市場的縣市：點了不出錯，圓環 0、完成率 0%。
- 補交紀錄：欄位和順序照 §5，台北時間（含跨日），CSV 跳脫逗號和引號、CRLF 換行。

## 3. 結果（2026-11-01）

- Node 端：43 項全部通過（含 Python 比對）。
- 瀏覽器端：21 項全部通過。第一次跑時空市場有 2 項失敗，已修正：

| # | 畫面 | 原本 | 修正後 |
|---|---|---|---|
| 1 | 總覽頁，選到 0 家的市場 | 提示寫「這個範圍還沒有**全部的**攤商」，下面的「顯示全部狀態」按了沒作用 | 「這個市場還沒有攤商」（縣市是「這個縣市還沒有攤商」），不顯示按鈕；篩狀態造成的空清單照舊有按鈕（`web/js/panels.js` 的 `renderVendors`） |
| 2 | 補交頁，選到 0 家的市場 | 攤商選單寫「請選擇攤商」，但沒有任何選項 | 「這個市場沒有攤商」，選單鎖住（`web/js/submit.js` 的 `renderSelects`） |

目前的正式資料每個市場至少 20 家，碰不到這兩個情況；修正是為了之後某個市場的攤商全部被排除時也不出錯。

另外發現匯入程式和網頁的網址規則有兩個小差異，正式資料都沒碰到，先記下不改：

- 長網址的 `0x…` 十六進位：網頁不分大小寫，Python 只認小寫。Google 產生的都是小寫。
- `cid=` 後面是全形數字（`１２３`）：Python 的 `isdigit()` 會當成數字接受，網頁不接受。
