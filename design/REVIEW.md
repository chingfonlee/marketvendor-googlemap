# SVG 元件化審查報告

- 審查日期：2026-10-31
- 審查範圍：`design/svg/` 底下現有的 27 個 SVG（原子元件 6、區塊組件 17、整頁 4）
- 審查方式：只閱讀檔案，沒有修改任何 SVG。

> 攤商補登頁的產生器 `tools/build_form_svg.py` 已經寫好，但**尚未執行**，所以還沒有補登頁的 SVG。為了裁切素材，曾執行 `crop_assets.py`，在 `assets/` 新增了 5 個 `form-*.png`。這次執行也覆寫了既有素材，但用的是同一份設計圖和同樣的裁切範圍。

## 結論

目前的 SVG **適合當作版面規格與視覺參考**，**不適合直接當成網頁元件使用**。主要原因：

1. **沒有任何可供 JavaScript 定位的標記**：
   - 27 個檔案的 `class`、`data-*` 都是 0 個。
   - `id` 只用在陰影濾鏡和裁切路徑。
   - 圖釘、徽章、表格列都是沒有名稱的 `<g>`、`<text>`，JavaScript 無從找到並修改。
2. **同一個外形重複畫了很多次**：
   - 圖釘外形在 `map-view.svg` 重複 27 次，在 `admin-map-view.svg` 重複 32 次，沒有使用 `<symbol>`／`<use>` 模板。
   - 範例資料（店名、數字、日期）直接寫死在 `<text>` 裡。
3. **地圖底圖本身畫有圖釘**：`map-taiwan.png` 和 `admin-map.png` 原本就畫了圖釘、城市標籤和對話框，向量圖釘是疊在同一位置把它們蓋住。只要 JavaScript 依資料改變圖釘位置，底圖上的舊圖釘就會露出來。
4. **多個 SVG 放進同一個 HTML 時，id 會衝突**：裁切路徑的 id 是自動編號的。`clip1`～`clip4` 各在兩個檔案裡出現，指的卻是不同形狀。陰影濾鏡 `shadow` 也每個檔案各定義一次。

可以沿用的部分：

- **座標系統**：所有組件都沿用整頁座標，viewBox 就是它在頁面上的位置，重組時不必猜。
- **狀態定義**：6 種地圖狀態和 4 種聯繫狀態的顏色、符號已經一致。
- **產生器**：`tools/*.py` 是唯一的產生來源。要修改時只動產生器，不必手改 SVG。

| 是否適合 HTML／CSS／原生 JS | 適合。版面用 CSS Grid；圖示 sprite、圖釘圖層、圓環用 SVG；其餘用 HTML | ✅ 不需要框架 |
