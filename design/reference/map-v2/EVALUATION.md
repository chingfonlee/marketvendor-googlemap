## 3. 座標轉換參考圖 `coordinate-spec.png`

這張的概念（經緯度 → 圖上像素）和表格格式都正確，經緯度數值也正確。但用它來定位會出錯：

1. **線性公式不適用於手繪地圖。** 公式把經緯度的外框直接等比例對應到圖上，但手繪島嶼的形狀和真實地理不一樣：西海岸被畫得比較往內。
   我把表格算出來的座標畫回這張參考圖上檢查（見 `coordinate-check.png`，紅色十字是表格的座標）：
   - 士林、羅東：偏差約 30～40px，還在陸地上。
   - 逢甲：偏差約 35px。
   - **花園夜市、瑞豐夜市：偏差約 100px，落在海裡。**

   也就是說，連這張圖自己的範例都對不上。
2. **地圖尺寸不一致。** 參考圖寫的是 898×1024，實際提供的乾淨地圖是 1122×1402，兩者的構圖範圍也不同，表格數字無法直接套用。
3. 只有 5 個參考點，不足以修正手繪地圖的變形。

**建議改用「夜市像素對照表」，不要用公式。**

- 系統是以夜市為單位做群聚，每家攤商直接沿用所屬夜市的位置，所以只需要知道**每個夜市**在圖上的位置。夜市數量有限，大約幾十個。
- 做法：在 `map-taiwan-clean.png`（1122×1402）上逐一標出每個夜市的像素座標，存成一份表格，欄位為：夜市、縣市、x、y。
- 名單出現表格裡沒有的夜市時，才用公式算近似位置，並標記成「待人工校正」。

## 1. 群聚標記規範 `cluster-marker-spec.png`

| 項目 | 評估 |
|---|---|
| 同一夜市合併成一個標記，顯示數量 | ✅ 正是需要的功能 |
| 數量文字、攤位圖示、底座陰影分開 | ✅ 方便用 SVG 組合，數字可以動態更新 |
| 夜市名稱標籤 | ✅ |
| 點擊後在原地展開個別攤商 | ✅ 適合 15 家以下的夜市 |
| **依數量決定顏色**（3＝橘、8＝紫、15＝藍、24＝粉紅、50+＝紅） | ❌ 跟狀態顏色衝突。例如瑞豐夜市的綠色「8」會被看成「已完成」，紫色、藍色、橘色也都已經代表某個狀態 |
| 狀態只畫了 3 種（已完成／未完成／已聯繫） | ❌ 跟第 2 張的 6 種不一致，也跟目前的狀態定義不同 |
| 展開後的個別攤商只用顏色區分，沒有符號 | ⚠️ 色盲使用者無法分辨，建議沿用有符號的圖釘（✓、?、✕…） |
| 50 家以上在原地展開 | ⚠️ 會擠成一團。建議超過 12 家時改成開啟清單面板 |

**修改建議**：

- 群聚標記統一用一個中性的品牌色。
- 大小可以依數量分 3 級。
- 標記外圈加一圈依狀態比例分色的環：綠色佔多少，就表示這個夜市完成了多少。管理者一眼就能看出各夜市的進度。

這張是規格圖，不是可以直接使用的素材。我會照它用 SVG 畫，**不需要再提供圖檔**。
